# LifeForge — контекст работы

- Проект на Go 1.26, PostgreSQL, Google OAuth/JWT, Google Calendar и GigaChat. Слои: `transport/http → service → repository`, связи через интерфейсы; SDK и SQL не переносить в сервисы. `main` — источник старых сценариев и макетов, не архитектуры.
- Контрольный коммит перед переносом: `1adfece` (`save`). Перенос календаря, чата, геймификации и интерфейса сохранён тематическими коммитами в ветке `planner`. Целевая ветка для последующего объединения — `improve-structure`. Не коммитить `.env`, credentials, OAuth-токены, `out/`.
- Обычный сайт: `http://localhost:5050`. Callback: `/api/v1/auth/callback`. Для текущего Docker-окружения нужны PostgreSQL **и port-forwarder**, порт базы 15432. Миграции 1–4; Windows-перенос миграций без bind mount: `scripts/migrate.ps1`. Не пересоздавать тома ради запуска.
- Google-токены отдельны по пользователям, AES-GCM в БД; общий `token.json` не использовать. Любое событие ИИ — черновик до подтверждения. Повтор подтверждения не должен создавать дубликат.
- Все даты UI и планирования — **Europe/Moscow, UTC+3**, независимо от зоны устройства. Регрессия: «четверг 19:00–21:00» не должен становиться понедельником; сверять дату/время сервером для однозначного одиночного запроса, не сдвигать неоднозначные планы вслепую.
- Дизайн: тёмный фон как в пользовательском fitness-reference, фиолетово-розовые/фиолетово-голубые градиенты, немного зелёного/голубого. Планировщик занимает почти весь экран, чат и календарь равной высоты. Минимум декоративных стрелок. Анимации учитывать `prefers-reduced-motion`.
- Есть две темы: тёмная и светлая с более выраженными закатными розово-персиково-сиреневыми градиентами в духе GTA 6. Переключатель в шапке, выбор в `localStorage` (`lifeforge.theme`); `theme.js` применяется до CSS, светлые переопределения — `theme-light.css`.
- «Мой герой»: профиль, круг XP, характеристики с ±, задачи Google Calendar, завершение (+10 XP, +2 монеты), история реальной активности. Никаких выдуманных процентов/статистики; повторное завершение не даёт награду.
- Текущий frontend: `static/app.html`, `app.js`, `planner.js`, `workspace.css`, встроен через `embed`: после правок пересобирать/перезапускать сервер.
- Проверки: `go test ./...`, `go vet ./...`, `go test -race ./...`, `node --test tests/frontend.test.cjs`. Реальные сетевые проверки отдельно от переносимых тестов. Не создавать события в личном календаре ради проверки без запроса пользователя.

- Названия новых веток предварительно согласовывать с пользователем; не добавлять префикс codex/.
