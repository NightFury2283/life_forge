# Тестирование LifeForge

Задание: проверить основную существующую логику, преимущественно модульными тестами, и добавить несколько интеграционных сценариев. Спецификация Life_Forge.docx использована как направление развития; будущие магазин, баффы, досье и подтверждение планов здесь не считаются реализованными.

## Запуск

```powershell
go test ./...
go vet ./...
go test -race ./...
go test ./internal/app -run TestIntegration -v
```

Нужен Go 1.26+. Для `-race` на Windows требуется доступный C-компилятор и включённый CGO. Ни один тест не читает личные credentials, `.env` или токены и не обращается к внешним сервисам.

## Модульные тесты

| Файл | Что проверяется |
| --- | --- |
| `internal/core/domain/stat_test.go` | Границы названия и описания, Unicode, пустые значения, отрицательное значение, переполнение PostgreSQL INTEGER, владелец |
| `internal/core/auth/jwt/jwt_test.go` | Выдача и разбор JWT, срок 24 часа, HS256, чужая подпись, другой алгоритм, alg=none, истечение и отсутствие срока, future iat, issuer, некорректный user ID/subject, повреждённый токен |
| `internal/features/auth/service/auth_service_test.go` | Полный сценарий обмена кода, передача контекста и аргументов, ошибки каждого этапа и остановка цепочки, отсутствие кода, OAuth state |
| `internal/features/users/service/get_profile_test.go` | Получение профиля, передача ID и контекста, сохранение исходной ошибки |
| `internal/features/gamification/service/stats_test.go` | Валидация до вызова repository, создание, дубликаты и ошибки repository, список, удаление, неверные ID |
| `internal/usecases/parsing_prompt_test.go` | Текст и JSON ответа ИИ, один объект и массив, фильтрация не-событий, даты с часовым поясом и UTC, optional-поля, неправильный JSON/даты, цели и прогресс |
| `internal/core/transport/http/request/decode_test.go` | JSON, required-поля, типы, неизвестные поля, лишние JSON-объекты и некорректные данные |
| `internal/core/transport/http/response/handler_test.go` | HTTP-коды доменных ошибок, JSON Content-Type, тело ошибки, явный и неявный статус HTTP, повторный WriteHeader |

Использованы стандартные `testing`, `httptest`, табличные тесты и `t.Run`. Независимые тесты запускаются через `t.Parallel`. Зависимости сервисов заменены небольшими реализациями интерфейсов, без новых библиотек моков. Ошибки проверяются через `errors.Is`, а не по тексту. Нет `time.Sleep`, зависимостей от порядка выполнения или настоящих OAuth-ключей.

## Интеграционные тесты

`internal/app/handler_integration_test.go` поднимает настоящий HTTP-сервер через `httptest.NewServer`. Используются общая сборка приложения, реальные роутер, middleware, JWT, сервисы и демохранилище в памяти. Только Google заменён управляемым тестовым провайдером. У клиентов отдельные cookie jar.

1. **TestIntegrationGoogleLoginAndProfile**: отказ без токена, недоступность демовхода в обычном режиме, OAuth redirect/state/callback → JWT cookie → профиль, выход, отказ с поддельным JWT, доступность страницы и JS.
2. **TestIntegrationStatsAccess**: Alice и Bob входят отдельно; некорректные запросы получают 400, запрос без JWT — 401, создание — 201, дубликат — 409. Bob не видит и не удаляет характеристику Alice; чужое удаление — 404. Cross-site запрос блокируется. Владелец успешно удаляет характеристику.
3. **TestIntegrationOAuthStateAndDemo**: неправильное состояние не допускает вход, повторное использование состояния не работает, явно включённый демовход даёт доступ к профилю.
4. **TestIntegrationRegisteredVersionedOAuthCallback**: вход через ранее зарегистрированные `/api/v1/auth/google` и `/api/v1/auth/callback` завершается выдачей JWT и доступом к профилю. Дополнительный модульный тест `oauth_test.go` проверяет сохранение redirect URI из credentials и явное переопределение адреса.

Это интеграция слоёв приложения, **не тесты PostgreSQL и не настоящего Google OAuth**. SQL-запросы, миграции на живой БД и реальный обмен с Google требуют отдельного окружения. На момент проверки движок Docker Desktop был выключен.

## Покрытие

Измерение по пакетам, в которых есть тесты:

```powershell
go test ./internal/core/domain ./internal/core/auth/jwt ./internal/features/auth/service ./internal/features/users/service ./internal/features/gamification/service ./internal/usecases ./internal/core/transport/http/request ./internal/core/transport/http/response ./internal/app -coverprofile=out/coverage
go tool cover -func=out/coverage
go tool cover -html=out/coverage
```

| Пакет | Покрытие statements |
| --- | ---: |
| domain | 100% |
| auth/service | 100% |
| users/service | 100% |
| gamification/service | 100% |
| usecases | 96,9% |
| http/request | 100% |
| http/response | 86,8% |
| app | 87,5% |
| auth/jwt | 58,3% |

В JWT-пакет также входят функции чтения конфигурации, которые здесь не покрываются; процент относится ко всему пакету. Эти числа не являются покрытием всего проекта. В установленном Go отсутствует служебный инструмент `covdata`, поэтому измерение `go test ./... -cover` для пакетов без тестов может завершаться ошибкой окружения. Приведённая команда с явным списком пакетов работает.

## Исправления, связанные с тестируемыми сценариями

Исправлены JSON Content-Type, статусы 400 для некорректного запроса, учёт неявного HTTP 200 при логировании, OAuth state, проверка алгоритма и обязательного срока JWT. Доступ к характеристикам ограничен владельцем из JWT. Удалены старые дубли с ошибками компиляции, исправлены синтаксис up-миграции и порядок удаления таблиц в down-миграции. Профиль получает корректный user ID, отсутствующий профиль возвращает доменную ошибку, неудачное подключение закрывает пул.

## Краткое объяснение для защиты

«Я проверил существующую бизнес-логику: валидацию характеристик, сервисы авторизации и профиля, JWT и разбор ответов ИИ. В модульных тестах зависимости подменяются через интерфейсы. Интеграционные тесты проверяют взаимодействие HTTP, middleware, JWT, сервисов и хранилища в памяти, включая изоляцию данных двух пользователей. Реальные Google API и PostgreSQL в этих тестах не используются».
